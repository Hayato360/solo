## Issues Encountered

### Bugs found and fixed
- **Circular require:** `PartyService` required `TargetService`, which already required `PartyService`. Fixed with a `SetTargetProvider` hook, matching the existing `GateService.SetEntryHandler` precedent.
- **`Escape` unusable as the release key.** Roblox owns it for its own menu, so the input arrives with `gameProcessed = true` and our handler ignores it — there was effectively no cancel. Replaced with **hold `R`** at the user's request.
- **Close targets were unlockable.** A bot 5 studs away at 111° failed the 75° cone and read as the key being broken. Added `CloseLockRadius = 25`: anything that close locks regardless of facing.
- **Cycle ping-ponged between two of three targets** (−75 → −89 → −75). Cause: candidates were ordered by screen angle, but the hard-lock camera re-centres on whatever is locked, reshuffling the list every press. Now cycling orders by **world-space azimuth** (camera-independent) while the first lock still uses screen angle. Verified −75 → −61 → −89.
- **Web layout:** `main` is a CSS grid, and grid items default to `min-width: auto`, so the flow strip widened the whole page and forced horizontal scroll at 775px. Fixed with `min-width: 0` on grid children.
- **Red screen border on swap** — see below.

### The red border diagnosis (worth keeping)
Roblox's built-in CoreGui health display tracks a single Humanoid and reads any drop as damage. Swapping repoints it at a **different body**, so going from a healthy Kang (308 HP) to a damaged Seoa (199 max) looks like a huge hit and flashes the damage vignette although nothing hit you. Seoa specifically because she is the squishiest (Mage, DEF 5) and therefore usually the one carrying damage.

Ruled out by measurement first:
- Health initialises correctly — `RigFactory.ApplyCombatStats` sets `Health = MaxHealth`.
- Regen covers **all** party Hunters, not just the controlled one.
- Seoa is not chronically low: Mina heals her at **~21 HP/s** (24 → 92 → 155 over 6s).

Fix: `StarterGui:SetCoreGuiEnabled(Enum.CoreGuiType.Health, false)` in `GuiController`. The party HUD already shows HP for all three Hunters, so the built-in one was redundant as well as misleading.
**Not visually confirmed** — `screen_capture` excludes CoreGui, so this is a reasoned fix awaiting the user's eyes.

### Balance finding (not fixed)
`ClassDefs.BaseRegenPerSecond = 0.004` is **0.4% of max HP per second** — roughly 200 seconds to full-heal Seoa. Effectively all healing comes from the Healer. If Mina dies or is not in the party, the team recovers at a crawl. Worth revisiting during Stage 5 tuning.

### Tool / MCP limits hit
- **`script_grep` only sees the client tree during Play mode.** It returned zero matches for `GetFocusTarget` even though `AIBrain` contains it. Use `execute_luau` on the Server datamodel to search source while playing.
- **`require()` from `execute_luau` returns a fresh module instance**, not the running one — the command bar has its own module cache. Two readings this session ("controllerTarget = nil", server "no lock") were meaningless because of this. Use observable state (attributes, Instances, GUI) instead.
- **`screen_capture` excludes CoreGui** — cannot be used to verify anything in the Roblox topbar, default health bar, or the damage vignette.
- Simulated keyboard still cannot press `1` (confirmed again). `2`, `3` and `R` work.
- **Studio was restarted mid-session** (the `studio_id` changed). All Edit-mode script changes survived, but this is a standing risk while the place is unsaved.
