กฎโครงสร้างสำคัญ

ใครรับผิดชอบอายุของวัตถุ?

  • Service เป็น singleton ที่ครอบครองระบบ เช่น GateService สร้าง ติดตาม และลบ Gate
  • Class คือวัตถุที่มีหลายตัว เช่น Gate, Hunter, Monster, DungeonInstance
  • Class ต้องมี Destroy() เพื่อตัด event และทำลาย Instance ที่มันสร้าง
  • Signal ใช้ประกาศเหตุการณ์ระหว่างระบบ เช่น Gate Stability หมด หรือปาร์ตี้ถูก wipe

ตัวอย่างเส้นทางข้อมูล

เมื่อผู้เล่นกด Enter Gate เกิดอะไรขึ้น?

  1. GateController แสดง GatePanel จาก rank, modifier, stability และ party power ที่ Server ส่งให้
  2. Client เรียก Remote เพื่อขอเข้า Gate ไม่ใช่คำสั่งย้ายตัวเอง
  3. GateService / DungeonService ตรวจว่า Gate เปิดอยู่ ปาร์ตี้เป็นของผู้ขอ ทุกคนเข้าได้ และยังมี dungeon slot
  4. DungeonService clone template ไปยัง slot ที่อยู่ไกลใน Workspace แล้วพา Hunter ทั้ง 3 คนเข้าไป
  5. DungeonInstance จัด wave, ประตู, boss และทางออก
  6. เมื่อจบ DungeonService ให้รางวัล ส่ง event ให้ Progression/Inventory/Quest แล้วคืน party และ slot

ความปลอดภัยของเกม

ทำไม Client แก้ Gold หรือดาเมจเองไม่ได้

Client รับปุ่มและแสดงผล แต่ไม่ใช่แหล่งความจริง Server ตรวจ ownership, ระยะ, cooldown, สถานะมีชีวิต และ state ของเกมก่อนแก้ข้อมูล

ข้อมูลถาวรผ่าน DataService และ ProfileService; WalletService เป็น API สำหรับ Gold/Diamonds

สัญญาระหว่างระบบ

dependency ที่ตั้งใจให้เปลี่ยนได้

Stage 5 ใช้ PlaceholderCombatService เป็นจุดกลางของ damage. Stage 6 ส่ง modifier เป็น attributes/stat data จึงเปลี่ยนเป็น CombatService และ DamageService ภายหลังได้

PartyService ยังเป็นเจ้าของปาร์ตี้และการสลับ Hunter แม้ Gate, Dungeon และ UI จะใช้ข้อมูลพลังของปาร์ตี้

Stage 6 รอการตรวจด้วยมือ

  • 6A: ProfileService store PlayerData_v1, ข้อมูลผู้เล่น, Gold/Diamonds และ session lock
  • 6B: EXP, level, rank, party editor และ party power
  • 6C: inventory, crafting, blacksmith, signature weapon, potion/trap
  • 6D: awakening และ Player Class
  • 6E: quest board, secret quest และ recruitment

  • รับ secret quest, recruit Hunter และใส่ปาร์ตี้
